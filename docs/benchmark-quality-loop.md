# 30 题修订复盘：最小质量闭环

本轮只做真实案例、离线测试、生成提示词的小改动和 10 场景对照。缺陷码是阅读索引，不是新的题集字段。实验结果见 [实验记录](../data/benchmark/quality_loop_v1/README.md)。

## 先澄清历史

- `pilot_v1/drafts` 保存首次生成阶段的产物；其中边界任务的空题面是自定义边界流程占位，不是 Ragas 生成失败。首次批次也使用了项目自己的抽样、风格和中文提示，不能把所有问题都归于“原生 Ragas”。
- `pilot_v1 → pilot_v2` 是重新生成，不是同一批题逐题修订。例如 0001 从著作权裁决救济变为个人信息执法措施；相同序号不构成来源关系，不能作质量配对。
- 可以明确追溯的是 `trial_v1` 中的 `pilot_v2-*` 等来源，经过 `trial_v2/revisions.jsonl`、收到的审核表、`trial_v3/revisions.jsonl` 到最终发布。0014、0030 等属于整题替换，不是参考答案润色。
- 最终 30 题为 28 道普通题、两道人工/agent 编写来源的边界题。历史的错误拒答题 0005 与错误澄清题 0015 被剔除；0010 的 `correct_premise` 被撤销。不能把最终题集视为三类边界行为都已覆盖。
- 最终签核记录明确为用户委托 Codex 审核，`human_per_item_review_claimed=false`。本复盘和新实验也是 AI 辅助工作，不冒称独立人工金标准。

历史文件保持原样；随仓库保存的 [11 个真实案例](../tests/fixtures/benchmark_quality_cases.json) 含原记录、修正记录、来源路径及内容哈希。完整历史仍保留本地，离线测试不依赖这些本地目录。

## 缺陷码与逐题回填

| 码 | 含义 | 判断边界 |
|---|---|---|
| S | 题目范围不受证据支持，或无关任务拼接 | 两份材料相关不等于同一个任务；明确子集问题可以成立 |
| C | 遗漏必要内容、适用条件或限定强度 | 只补题面范围内的要点，不能无条件要求列出整个章节 |
| E | 证据不充分、错位、结构损坏 | 表格和标题是复核提示；前言定义不自动算坏证据 |
| P | 评分点不必要、非原子化或题面已经给出 | 不把参考答案越长视为越好 |
| L | 标签与实际内容不一致 | 生成目标不是最终标签，跨 block 不一定是多跳 |
| B | 拒答、澄清或纠错依据不成立 | 检索未命中不能证明无答案；纠错必须有明确反证 |

## 本轮具体改变与学习结论

实验只调整生成与标注提示词，版本 4 → 5；保持现有三次标注尝试上限（原稿＋最多两次修复），不加新的模型阶段和审核接口。**对照未证明整体改善，因此默认生成提示词已恢复 v4；试验 v5 保存为 `quality_loop_v1/candidate_prompts.json`，由一次性脚本加载。**

1. 先明确一个业务任务和适用对象，再要求完整回答这个范围。问全部才补全适用枚举，明确问子集就不强补范围外内容；保留主体、前提、例外和“应当/可以/原则上”。
2. 清除“必须满足多跳目标”与“按实际内容标注”的冲突。无法构成共同任务时允许收窄，真实多来源覆盖的下降则在实验中显式报告。
3. 缩短证据要同时检查题面前提；题面已经给出的事实不独立计分；删去无依据数值问题时仍保留原文已有的数量要求。

没有新增内容关键词守卫：上述未解决问题主要是语义问题。实验结束后仅补了已有上下文扩展的普通 `- ` 列表识别，使矿山场景包含末项780且不跨入781新章节。这是默认流程唯一的生产代码改动；已有公式、导航守卫只补真实坏例。

固定节点只适合本次对照：原代码将批次目录名混入抽样种子，换目录也换了材料。实验直接复用同一 task 和节点，调用已有 `generate_one`；不改正式生成入口。后续扩量仍轮换节点。即使输入完全相同，模型也不保证逐字复现。

## 怎么运行

在仓库根目录、`conda rag` 环境运行：

```powershell
python -m unittest discover -s tests -p test_benchmark_quality_loop.py -v
```

测试夹具包含 11 个历史案例，另含本次实验发现的1个无序列表截断输入；客观坏例检查具体问题，修正例通过原文与内容校验。表格补全、合法前言定义、明确子集另外有正例保护。语义案例保存供复核，测试通过不等于机器已识别这些语义缺陷。

一次性实验命令：

```powershell
python scripts/experiment_quality_loop.py
```

需本地 KG 和环境变量 `DEEPSEEK_API_KEY`、`DASHSCOPE_API_KEY`。第一次运行先保存 5 历史＋5 新场景，随后两个流程共 20 次场景生成；已完成任务不会重新调用。新场景排除旧任务节点对应的原文 block 重叠，但不声称未见过同一文档或不存在语义近重复。继续运行只补未完成的实验步骤；另一次实验应明确使用新的输出目录，并复制 baseline_prompts.json 和 candidate_prompts.json 作为两组配置，不能覆盖本次证据。

实验保留初稿、标注、修复、自检、Qwen 辅助评审及用量。Qwen 不看流程身份、最终金标准或生成模型自检结论；这有助于减少偏向，但不是独立人工标注。本轮所有材料只作 dev，不进入 holdout。
