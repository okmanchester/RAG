# MySQL 全文检索与 Elasticsearch 对照：2026-10-16

本轮实测中，ES CJK＋BM25 的四项总体检索指标均高于 MySQL InnoDB ngram 自然语言检索。Top-10 证据组召回率高 5.21 个百分点；全部证据命中率高 8.33 个百分点，相当于在 120 道适用题中净多完整命中 10 道题。MySQL 可以有效检索这批中文语料；本轮提供的是当前两套具体配置的效果差异，不证明 MySQL 经其它分词、查询或排序优化后仍然落后。

## 输入与隔离

- 使用 `data/benchmark/gold150_hard_v2`：33 份文档、1,308 个有效切块，150 道开发题。政策、技术各有 60 道回答题参与质量评分，另外 30 道边界题仅运行检索。没有改题、生成回答或调用 LLM。
- 正式运行时间为北京时间 2026-10-16 22:13:06—22:14:48。MySQL 8.4.11；ES 9.5.5；本地 BGE 1024 维归一化向量复用原缓存，模型、语料及缓存 SHA256 均记录。
- 使用隔离数据库 `rag_test_fulltext_eda4eddff4c247e7bd299bf9c8e10814` 和同 UUID 的 `rag-test-fulltext-*` 索引。没有导入业务知识库、切换 alias 或调整正式默认模式。
- 文本和原始问题相同，只包含可检索切块；两边固定按 chunk ID 处理同分。检索代码只接收问题，不接收参考答案和金标准证据。

## 配置与效果

MySQL 使用 InnoDB、`utf8mb4_0900_ai_ci`、`FULLTEXT(text) WITH PARSER ngram`、`ngram_token_size=2`、`MATCH(text) AGAINST(... IN NATURAL LANGUAGE MODE)`。默认停用词和关闭停用词各建一张独立表；没有使用全文句子布尔短语查询，也没有根据答案逐题构造关键词。

ES 沿用单分片、零副本、内置 `cjk` 与默认 BM25。混合检索的向量字段为 `index=false`，使用精确 cosine，两路各取 50 条，以应用侧等权 RRF、常数 60 融合，最终取 Top-10。

评分复用现有 metric v2 的物理来源／文本证据命中规则；证据组召回为逐题计算后取均值，全部证据命中为一题所有证据组均命中才记 1。

| 路径 | 证据组召回@5 | 证据组召回@10 | 全部证据命中@5 | 全部证据命中@10 |
|---|---:|---:|---:|---:|
| MySQL 默认停用词 | 76.99% | 86.88% | 60.83% | 77.50% |
| MySQL 关闭停用词 | 76.99% | 86.88% | 60.83% | 77.50% |
| ES BM25 | **85.33%** | **92.08%** | **72.50%** | **85.83%** |
| ES 混合 | 82.25% | 89.57% | 70.00% | 83.33% |

关闭 MySQL 停用词后，12/150 题的 Top-10 顺序或集合有变化，但这四项证据指标和分组指标均未变化。因此，本轮不能把差距归因为默认停用词，也不能说停用词配置完全没有作用。

|---|---:|---:|---:|---:|

## 延迟

单并发，150 题完整预热一轮后测三轮，每条路径 450 个样本。题序和路径顺序以固定种子 20261016 打乱。各轮返回排名均稳定，统计范围统一为发出检索请求到取得候选 ID，包含客户端开销，不包含业务状态校验、来源回填或证据评分。

| 路径 | median，ms | p95，ms |
|---|---:|---:|
| MySQL 默认停用词 | 4.46 | 6.40 |
| MySQL 关闭停用词 | 4.49 | 6.43 |
| ES BM25 | 3.93 | 5.48 |
| ES 混合，不含查询 embedding | 16.71 | 21.63 |
| ES 混合，含当次查询 embedding | 78.84 | 269.66 |
| 查询 embedding 单独计时 | 60.53 | 251.31 |

包含 embedding 的混合检索直接测量整个过程的分位数，没有把两个 p95 相加。两种词法检索在当前小规模语料上都为毫秒级；约 0.53 ms 的 median 差异不足以据此宣称生产性能优势。历史管理检索耗时包含 MySQL 状态校验，本轮不与其直接比较。

## 补充归因：固定分词后的评分消融

随后在独立临时索引上保持 CJK 分析器、1,308 个切块、原始问题及排序规则不变，只改变相似度参数。默认 ES 在 150 题的 Top-10 顺序和指标均精确复现原运行；另外重建的 MySQL 在四道诊断题上也复现了原 Top-10 顺序。

| 固定 CJK 的评分配置 | 证据组召回@10 | 全部证据命中@10 |
|---|---:|---:|
| BM25 默认，k1=1.2、b=0.75 | 92.08% | 85.83% |
| 关闭长度归一化，k1=1.2、b=0 | 92.92% | 86.67% |
| 近似线性词频，k1=1,000,000、b=0.75 | 85.63% | 75.83% |
| 近似线性词频，同时关闭长度归一化 | 85.14% | 73.33% |
| 脚本评分 Σ query.boost × TF × log10(N/df)²，无长度归一化 | 86.81% | 77.50% |
| 原 MySQL ngram 自然语言模式，参考 | 86.88% | 77.50% |

最强的归因证据指向词频饱和：在同一套 CJK 分词下，削弱 BM25 的词频饱和就使召回明显下降；改为 TF×IDF² 的线性词频评分后，指标接近 MySQL。不能据此分解出每个机制对原 5.21 个百分点差距的独立贡献，因为 IDF、查询词权重、分析器细节和参数交互仍有差异。脚本评分也不是 MySQL 的逐分精确复刻。

长度归一化不是本轮 ES 优势的必要条件：去掉它仍然保持优势，Top-10 指标甚至略高。不过召回@5 从 85.33% 变为 85.06%，存在指标权衡；这是同一开发集上的诊断，不构成修改默认配置的依据。

### 实际排序证据

- `batch_001-0009`：问题要求监管规则制定方和投诉渠道。诊断重建中，MySQL 将《工业数据分类分级指南》的泛相关段落排第 1，金标准段落排第 13；ES 将金标准排第 2。泛相关段落中“分类”出现 7 次、“分级”出现 9 次，金标准段落各出现 1 次。MySQL 原生单词查询的对应分数比恰好为 7 倍和 9 倍，显示重复词在线性累加。ES explain 显示有限的 k1 饱和项，并能给“监管”“投诉”等其他匹配词保留较强贡献。相同分词下改为接近线性词频，金标准退到第 8；再关闭长度归一化退到第 9。
- `batch_002_64-0024`：补齐工业平台资源管理能力的证据分布在两个切块中。其中包含开发社区、测试发布及数据资源管理的短块，MySQL 排第 12，ES 排第 2。MySQL 已找到另一关键块且排第 1；因为金标准把四段要求放在同一证据组，缺失最后一块会令该组召回从 1 变成 0。这是 Top-K 截断与证据组覆盖规则共同放大的差异，不能解释为整题完全没有找到相关内容。
- `batch_002_64-0027`：关于报告和定期评估的《数据安全法》关键块，MySQL 排第 13，ES 排第 6。关闭长度归一化仍在第 5；将词频改为近似线性后退出 Top-10，支持词频饱和的重要性。

本轮主差异体现在相关证据是否进入 Top-K，以及多条件证据是否完整；MySQL 的这些失败案例仍能匹配到目标切块。两边主要使用中文二元切分，ES 没有启用领域词典或语义理解能力，不能把结果解释成 ES “更懂中文”。此前关闭 MySQL 停用词未改善指标，也不支持将停用词视为主因。

归因消融的 750 条路径／题目结果已独立重算并通过产物哈希检查；临时数据库、授权和 5 个 ES 索引均已清理，未修改正式配置、未调用 LLM。诊断脚本、完整结果和 explain 原文位于 [诊断目录报告](../tmp/mysql_es_diagnosis_20261016/report.json)。
