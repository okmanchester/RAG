# 全量150题中15道评分失败的原因分析

用户授权实施后，原15题已全部恢复，当前实现与全量结果见 [评分修复记录](benchmark-scoring-fix-v2-20261013.md)。以下保留修复前的诊断依据。

本次仅做离线分析，未调用模型、未修改题库或评分实现、未改写已保存分数。分析对象为本轮15道持续评分失败题，逐题检查最终错误、三轮判定/修复历史、真实回答、实际引用的Top-10上下文及校验代码。

## 结论

这15题的最终失败均是评分协议v2的grounding校验错误，不是回答生成失败。原因同时涉及评委引用抄写/定位错误、引用解析代码缺陷，以及单次校验失败阻断整份判定的设计。拦截部分错误是必要的：已经观察到评委用金标准内容为回答未出现的表述给correct的情况。

| 主要原因（每题归入一组） | 题数 |
| --- | ---: |
| 仅排版空白不一致 | 4 |
| 回答引文来自材料/金标准，或被改写拼接 | 3 |
| 省略Markdown标题加粗标记 | 1 |
| 把不连续的两段法条拼成连续引文 | 1 |
| 错选上下文、引用缺失条款、重构表格内容 | 5 |
| 句号后引用解析错误，加上原子主张重复判定问题 | 1 |

三轮评分成功数为126→133→135；15题最终仍未完成。每题保存了三轮、每轮两条逻辑判定/修复尝试记录；HTTP内部重试次数不等同于这些逻辑记录。12道困难题、2道中等题、1道澄清题；评分缺失集中在复杂题，已评分子集可能存在选择偏差。

## 评分器已确认的问题

### 1. 句号后引用被绑定为空

当前 [extract_citations_v2](../rag/benchmark/scoring_v2.py) 从引用位置向前寻找最后一个句号作为主张起点。对“工业企业结合生产制造模式。[1]”得到claim空字符串、response_span两端相等；无法覆盖真正的句子。

离线扫描完整150条回答，仅batch_001-0042出现该模式，共4处空引用片段；此次没有发现其他成功评分题包含空片段。这是本轮可定位的代码缺陷，并非笼统推测影响所有题。修复应同时覆盖句号前后引用、连续引用组、引号、段落和同句多次引用，不要把引用无限向前扩展。

### 2. 相同引文不等于重复事实

grounding_issues以(response_quote, citation_index)作为重复键。batch_001-0042中，生产/服务运营模式与行业/规模条件是不同事实，却引用了同一完整句子；工业/平台数据域也是同样情况。原子化任务允许多个不同事实来自同一句话。目前可以让评委选不同短片段绕开，但更可靠的是区分事实身份与支撑片段，既允许共享证据，又阻止重复事实增加引用覆盖率。

### 3. 引用评分错误连带丢弃答案评分

score_judgment_v2先校验整份judgment，任意问题都会raise；evaluation.py只有整份计算成功后才写入内容/边界/引用指标。因此，即使错误仅在支持引文中的排版空格，答案要点评分也会缺失；澄清题也被与边界行为无关的引用错误阻断。

可以按依赖关系分别校验和出分：要点指标依赖有效point_verdicts和回答引文；边界行为指标依赖有效boundary_correct；引用指标依赖有效claims、引用绑定及支持证据。各指标保留自己的错误与完成率。边界判定仍需检查实际回答，不能仅凭一个布尔值无条件通过。

## 为什么三轮重试作用有限

1. temperature固定为0，材料与核心评分任务基本不变；低温不是严格确定性，但错误模式容易重复。
2. 恢复提示携带上一次无效judgment和validation_issues；可能有助于修复，也可能让同一个错误引文反复出现。这里只能确认历史中重复错误，不能从日志证明模型内部的锚定机制。
3. quote_candidates按文本相似度取最多3段，提供的是原文字符串，没有可直接选择的稳定片段ID，也不能保证跨表格行的语义组合已经准备好；候选相似度不能替代语义支持判定。
4. 某些任务本就无法靠逐字复制单段完成：需要两段supports、同处引用中更换为正确context，或将不被引用材料支持的claim判false。重复“修复全部错误”没有改变输出任务的难点。

604条已记录的评委HTTP响应均为200，15题最终错误均为ValueError校验错误，日志未呈现请求级网络/限流错误。其中1条completion_tokens达到4096；日志未存finish_reason且缺少逐请求题目关联，因此不能完全排除个别调用截断，也无法归因到这15题中的某一题。截断不是已证实的共同原因。

## 建议实施顺序

**第一步：修复明确的解析缺陷，补有意义的回归测试。** 覆盖句号后的引用绑定、不同事实共享句子、无效编号和同句多处引用。保证仍无法用未引用上下文为主张加分。

**第二步：让评委选择片段，程序负责复制原文。** 对回答和已检索上下文建立带原始字符区间的片段ID；评委输出片段选择及语义判定，原文字符串由程序生成。表格以原始行/单元格片段提供，不把未检索到的表头或正文加入评测上下文。若保留当前schema，也可先由程序准备精确候选，再让评委选择；需要的新输出字段应明确记录schema/协议版本。

**第三步：分开处理定位修复与语义重判。** batch_001-0048的引文在同处实际引用的context 2中，可由确定性检查发现；定位修复需记录来源并重新验证。batch_001-0054引文仅在未引用[1]中，不能以此改成支持。批量删除空格、Markdown符号或模糊匹配后直接给予correct/true会掩盖数值、否定词、条件或引用范围错误，不建议使用。

**第四步：按指标依赖分别校验，保留局部有效结果。** 引用支持出错时保留经独立验证的答案要点/边界结果；回答引文字段出错时，要点指标继续缺失，不能直接采信原来的correct。保持缺失评分与baseline错误分开统计。

**第五步：先用这15条保存回答验证修复，再统一重评150条保存回答。** 无需再做BGE检索或DeepSeek生成。先检查程序测试及原文核对，再按需要调用评委。修改评分实现、schema或rubric后应使用新目录及新身份指纹，保存当前结果；新旧评分不得无说明拼成一套。

通过标准应包含：句号后引用能正确定位；共享句子的不同原子事实可保留；每条引文能映射到原始回答或实际引用的上下文；不连续证据分别引用；回答未涉及的内容不能由金标准补齐；各指标给出真实完成率。没有进行模型复跑，尚不能保证以上改动能够让15题全部成功，也不能把它们当前的无效判定视为已经正确。
