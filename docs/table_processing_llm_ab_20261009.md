# 表格边界真实 LLM A/B 结果

日期：2026-10-09。结论：本次项目侧 DeepSeek 边界判断没有带来净改善，时间戳续接及部分检索指标回退，**不启用项目 LLM 默认开关，不替换现有规则产物或生产索引**。

## 实验范围与授权

用户明确授权将五组测试文档中九个跨页边界的表头、父字段及前后各最多两条记录文本发送到 `https://api.deepseek.com/chat/completions`。此次各边界串行请求一次，共九次，无重试、无第二轮提示词实验；不上传 PDF 或截图。此前笼统授权被自动审批拒绝的调用没有执行，取得具体授权后本次联网执行通过审批。

模型 `deepseek-flash`，提示词 `table_boundary_context_v1`，思考关闭，JSON 输出，最大输出 512 token，单次超时 45 秒。密钥从环境变量读取，不写入产物。复用五组已校验的原生 Middle JSON，未重新运行 MinerU 或原生 `cell_merge` 判断。A 是已经修复的规则方案，B 是相同后处理链路开启项目 LLM 边界分类器；修复前产物另作检索参照。

## 九个边界的结果

共七个返回值通过决策校验，两个记录为 `ValueError`。七个合法决策中，仅两个“新记录”与规则一致并被采用；四个“新记录”与规则支持的父字段延续冲突，一个“不确定”与时间戳续行证据冲突。连同两个失败记录，共七个边界进入保留原片段、告警的处理路径。

| 样本与物理页 | 规则决策 | 保存的模型决策／错误 | 应用结果 |
| --- | --- | --- | --- |
| 监测 9→10 | 新记录 | 新记录 | 采用 |
| 监测 10→11 | 父字段延续，第 1–5 列 | 新记录 | 拒绝，保留原片段 |
| 监测 11→12 | 父字段延续，第 1–5 列 | `ValueError` | 保留原片段 |
| 监测 12→13 | 父字段延续，第 1–5 列 | `ValueError` | 保留原片段 |
| 服务商 13→14 | 父字段延续，第 1、2、7 列 | 新记录 | 拒绝，保留原片段 |
| 分类 11→12 | 父字段延续，第 1 列 | 新记录 | 拒绝，保留原片段 |
| 芯片 23→24 | 父字段延续，第 1、2 列 | 新记录 | 拒绝，保留原片段 |

| 标签 29→30 | 记录续行，拼接第 3、4 列 | 不确定 | 拒绝，保留原片段 |

当前产物不保存原始响应或详细异常信息，两个 `ValueError` 不能进一步区分为输出未完成或决策校验失败，不能推测具体模型内容。实验确认请求执行及七个可校验返回，不能将九个请求全部标为语义成功。

## 结构与来源验证

两组均保持 17 个物理片段、8 张逻辑表、15 个可见物理表头。A 的六项质量检查全部通过；B 四项通过、两项失败，失败项均涉及时间戳：第 3 列仍为 `20251015083015000000`，没有接上 `86400`；B.2 逻辑行数仍为 12，未达到预期 11。第 4 列说明也未续接。

B 未执行六个父字段边界的逻辑锚点统一。监测、服务商、分类和芯片四份文档的有序 chunk `text` 仍与 A 完全一致；这说明文本相同不能证明逻辑锚点及跨度正确。标签文档 A 有 7 个 chunk，B 有 6 个；总数从 61 变为 60，减少数量源于续行未拼接后切块改变，不作为改善指标。

五份 B 产物均通过物理原文覆盖、派生来源映射、400 token 预算及确定性重放校验。另在清空密钥、将网络调用替换为立即失败的环境中重新验证五份产物，全部通过，证明重放只使用保存的判断。这些检查证明来源与处理链路完整，不证明模型判断准确。

监测第 12 页的分隔线／单位冲突和标签第 29 页的文字顺序仍保留为待复核；本次没有要求模型重写或强制合并这些内容。

## 冻结问题检索对比

使用同一个本地 BGE-large-zh-v1.5、查询指令及余弦排序，重新评估修复前、规则 A、LLM B 三份语料。15 道问题及真实单元格来源沿用既有冻结集合，未根据模型结果改题。

| 指标 | 修复前 | 规则 A | LLM B |
| --- | ---: | ---: | ---: |
| Top-1 原始证据完整率 | 6/15 | 8/15 | 7/15 |
| Top-5 原始证据完整率 | 14/15 | 13/15 | 13/15 |
| Top-10 原始证据完整率 | 14/15 | 14/15 | 14/15 |
| Top-1 列上下文完整率 | 5/15 | 8/15 | 7/15 |
| Top-5 列上下文完整率 | 11/15 | 13/15 | 12/15 |
| Top-10 列上下文完整率 | 11/15 | 14/15 | 13/15 |

相对 A，B 的 Top-1 原始证据与列上下文都改善 `labels_dynamic_id`，回退 `classification_electronics` 和 `labels_timestamp`；Top-5／Top-10 列上下文仅回退 `labels_timestamp`，没有改善项。Top-5／Top-10 原始来源指标相同，但时间戳完整列值消失，说明只检查原始来源召回会遗漏续行语义问题。分类文档的文本未变仍出现排名变化，是整个候选语料变化后的检索结果；本次未做排名原因归因实验。

此前规则 A 相对修复前的 `monitoring_new_modes` Top-5 来源回退仍存在。15 道开发问题和一次模型实验不足以推断全部语料准确率或模型稳定性；列上下文完整率是有来源约束的结构指标，没有执行回答模型评测。

## 处置与后续修复依据

保持 `table_processing.llm_enabled: false`。现有规则的时间戳拼接及父锚点合并保留，B 只用于实验复查，不重建全量生产索引。原生 MinerU 配置保持原状。

后续提示词需明确“子记录是新记录”与“父字段同时延续”可共存，避免返回 `new_record` 就遗漏父列操作；时间戳约束应更清楚说明日期时间前缀、间隔后缀和未结束说明的联合证据。失败产物应增加不含原始文本与密钥的失败阶段／校验原因码，以区分未完成输出和结构错误。这些是本次结果支持的修复方向，本次未修改提示词后再次请求模型。
