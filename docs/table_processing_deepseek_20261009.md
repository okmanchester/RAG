### 时间戳仍然错误

原生提示确实发送了下列边界内容：

```text
上一页： ["时间戳", "24", "20251015083015000000", "表示2025年10月15日上午8点30分"]
当前页： ["", "", "86400", "15秒开始传输,时间间隔为1天。"]
```

DeepSeek 返回 `[1,1,0,0]`：它标记了前两列，却没有标记示例数据和说明这两列。合并后的原生 Markdown 仍为：

```text
时间戳 | 24 | 20251015083015000000 | 表示2025年10月15日上午8点30分
       |    | 86400                | 15秒开始传输，时间间隔为1天。
```

预期数据 `2025101508301500000086400` 未得到，表 B.2 仍是 12 行（含表头），没有消除这条续行。

这是本次原生提示下的**判断遗漏**。接口返回成功、数组格式通过校验，不能据此认定判断语义正确。原生提示只含边界两行，没有表头、完整记录、页面图像或针对数字与说明续接的专门约束。本次没有追加不同提示重试，因此不能把单次结果当成 DeepSeek 在改进上下文后的能力结论。

### 继承的 rowspan 标志没有落实

本地 `docvortex/content/table/content.py::_apply_cell_merge()` 读取前页最后一行的显式 `<td>/<th>`，建立可转移单元格映射。它没有把跨多行的父单元格原始锚点一起纳入转移目标，也没有根据这些标志扩展父单元格的 rowspan。

因此上述其他返回 `1` 的列虽然在提示的视觉边界行中存在，前页 HTML 最后一行却没有对应显式单元格。服务商前页最后一行仅含第 4、5 列；分类表仅含第 2、3 列；芯片表仅含第 3、4 列。对应父字段不会被这段实现续接。没有出现模型标志直接导致的重复父字段文字，但跨页父单元格仍保持分页结构。

## 后续优化方向

本次证据支持分开处理两类问题：

1. **判断上下文**：在原生边界两行之外加入表头、字段类型和邻近记录；明确区分“新记录”“同一记录的后续数据”“父单元格重复显示”，并验证实际需要接续的非空数据／说明列。单次格式合法的数组不能作为最终质量判定。
2. **合并实现**：映射到继承 rowspan 的原始锚点，支持续接文字、相同父值去重、跨度扩展，并保留所有来源。否则模型正确标记父列也不能形成正确的逻辑表。

项目适配层仍需消费续表与单元格关系，才能让优化后的原生结果进入检索 chunk。本次仅完成启用、真实复跑及对照，没有进一步修改原生提示、docvortex 合并逻辑或项目表格分组。
